# VoltEdge Project Context

Дата обновления: 2026-05-20

## Назначение проекта

VoltEdge - статический лендинг для услуг электромонтажа под ключ в Алматы и Алматинской области. Главная задача страницы: объяснить инженерный подход, показать доверие через кейсы и гарантии, дать предварительный расчет стоимости и перевести пользователя в заявку.

## Текущая архитектура

- `index.html` содержит разметку лендинга, SEO-мета, секции страницы, форму заявки и редакт-панель.
- `styles.css` содержит визуальную систему, адаптив, UI калькулятора, Figma room animation и стили редакт-панели.
- `script.js` содержит калькулятор, анимации, форму заявки, локальные настройки и логику редакт-панели.
- `PROJECT_ANALYSIS.md` хранит анализ проекта, выполненные задачи и заметки по архитектуре.

Проект не использует сборщик. Страницу можно открыть напрямую или через локальный сервер.

## Основные блоки лендинга

- Hero: оффер, CTA, телефон, trust-метрики и визуальный блок.
- Trust strip: быстрые доказательства надежности.
- Problem section: риски электромонтажа без проекта.
- Advantages: преимущества инженерного подхода.
- Services: услуги для квартир, домов, бизнеса и щитов.
- Cases: примеры объектов и ориентиры по стоимости.
- Process: этапы работы от осмотра до сдачи.
- Guarantee: гарантийные условия и документация.
- Reviews: отзывы клиентов.
- Calculator: интерактивный расчет стоимости.
- FAQ: ответы на частые вопросы.
- Lead form: форма заявки.
- Footer: навигационный и контактный финал.

## Редакт-панель

Редакт-панель встроена в `index.html` и управляется через `script.js`.

Источник правды для настроек:

- `defaultSettings`
- `siteSettings`
- `localStorage`
- `BLOCK_SCHEMA`

Модель блоков хранится в `siteSettings.blocks`. Для каждого блока предусмотрены:

- `blockId`
- `blockType`
- `title`
- `subtitle`
- `description`
- `items`
- `media`
- `cta`
- `settings`
- `isVisible`
- `order`

Вкладка `Блоки` позволяет редактировать реальные секции страницы. Логика UX: выбрать блок слева, отредактировать поля справа, нажать `Сохранить изменения`. Фон редактора больше не размывается, чтобы список блоков и форма редактирования читались без визуального конфликта.

Вкладка `Анимации` также содержит инструменты Figma room animation:

- включение debug-режима слоев
- длительность transition
- inactive/active opacity
- сила smart grid opacity
- decor glow
- скорости smart lines, pulse и security blink
- energy thresholds `low`, `mid`, `high`, `max`
- preview presets: Base, Smart, Decor, Security, Commercial, Premium
- rapid test для быстрой проверки переключения состояний

Временный dev-вход без пароля включается флагом `DEV_AUTH_BYPASS` в `script.js`. Для production нужно вернуть `false`.

## Калькулятор

Калькулятор расположен в секции `#calculator` и управляется через:

- `CALC_CONFIG`
- `calculatorState`
- `getEstimateBreakdown()`
- `calculateEstimate()`
- `getCalculatorPayload()`
- `renderCalculator()`

Пользователь выбирает:

- тип объекта
- площадь
- количество комнат или зон
- тип ремонта
- пакет услуг
- дополнительные опции
- срок выполнения

Расчет учитывает базовую ставку за квадратный метр, коэффициенты пакета и ремонта, фиксированные и пометровые стоимости дополнительных опций, коэффициент срочности.

Калькулятор обновляет CSS-модель дома:

- smart home включает smart-состояние
- декоративный свет включает подсветку
- камеры включают security-состояние
- коммерческая нагрузка влияет на энергетику
- EV charger включает `is-ev` и усиливает левую/техническую подсветку
- premium-пакет включает полный визуальный набор: smart, decor, security и усиленный glow

Вся визуализация должна быть derived state от `calculatorState` и `getCalculatorPayload()`, без накопления старых классов после rapid interaction.

## Связка калькулятора с формой

При отправке формы заявки расчет прикрепляется к payload. В форму попадают:

- `calculatorPayload`
- `estimatedPrice`
- `calculatorArea`
- `calculatorOptions`
- `calculatorBreakdown`
- `calculatedAt`
- `leadSource`

Отправка сейчас не уходит на backend или CRM. Форма готовит клиентский payload и сохраняет его в `window.lastLeadPayload` для проверки и дальнейшей интеграции.

## UI/UX принципы проекта

- Темная инженерная эстетика без перегруза декоративными эффектами.
- Основной акцент: electric blue, дополнительный акцент: safety orange.
- Калькулятор является главным интерактивным блоком.
- Редакт-панель должна расширяться через существующую структуру, без дублей админки.
- Адаптив важен для hero, калькулятора и формы.
- Нельзя ломать текущий пользовательский поток: оффер -> расчет -> заявка.

## Правила дальнейших изменений

- Не переписывать проект с нуля.
- Сохранять статическую архитектуру, если задача не требует backend.
- Для новых настроек использовать `siteSettings` и существующую редакт-панель.
- Для новых секций расширять `BLOCK_SCHEMA`.
- Для калькулятора менять данные через `CALC_CONFIG` или настройки редактора.
- Для Figma room animation менять UX-настройки через `siteSettings.calculator.visual.animation`; координаты SVG остаются в `docs/figma-room-layer-coordinates.md`.
- Проверять `script.js` через `node --check script.js`.
- После визуальных изменений проверять desktop и mobile.

## RAG-база знаний

Папка `docs/` является источником документов для локальной RAG-базы. Сюда можно добавлять:

- технические задания
- бизнес-описания
- дизайн-решения
- промты
- баги и решения
- требования к калькулятору
- правила редакт-панели

Скрипты в `rag/` индексируют эти документы в локальную ChromaDB и позволяют получать релевантный контекст по вопросу.

Для истории решений и последних UI-правок смотри `docs/project-changelog.md`.

## Figma room animation baseline 2026-05-18

- Анимированная модель помещения в калькуляторе теперь использует `assets/figma-room/`.
- Источник текущей калибровки: `C:/Users/user/Downloads/Frame 369 (1).svg`.
- Все SVG-слои комнаты приведены к общему `viewBox="0 0 2801 1796"`, поэтому overlay-светильники и reflections фиксируются full-frame CSS-координатами и не съезжают относительно базы.
- Основной CSS-контракт: `.house-stage`, `.room-model`, `.room-layer`, `.room-light-*`, `.room-window`, `.room-reflection-*`, `.room-ambient`, `.room-smart-grid`, `.room-security-dot`.
- Карта координат и состояния анимации зафиксированы в `docs/figma-room-layer-coordinates.md`.
- Тестовая baseline-страница создана в `baselines/figma-room-animation-test/`.
- Debug mode: `?debugRoomLayers=1#calculator`, `?roomDebug=1#calculator` или `window.setRoomLayerDebug(true)`.
- Debug mode не должен принудительно показывать скрытые слои. Он добавляет outline, а подписи `.room-layer-label` показываются только при hover/focus, чтобы smart grid и security dots не выглядели включенными постоянно.
- Последний аудит: `docs/project-audit-2026-05-20.md`.
