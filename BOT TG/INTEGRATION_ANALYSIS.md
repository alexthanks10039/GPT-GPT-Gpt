# Integration Analysis

## Цель

Совместить два направления проекта:

1. Основной сайт VoltEdge - лендинг с калькулятором и формой заявки.
2. Telegram Mini App - мобильный интерфейс внутри Telegram для объектов, сотрудников и фотоотчётов.

## Текущее состояние сайта

Сайт уже реализован как статический лендинг.

Основные файлы:

```text
index.html
styles.css
script.js
```

Уже есть:

- оффер и CTA;
- блок услуг;
- кейсы;
- процесс;
- гарантии;
- FAQ;
- интерактивный калькулятор;
- форма заявки;
- сбор данных калькулятора в JS;
- подготовка `leadPayload` при submit формы;
- локальная edit panel.

## Проблема

Сейчас форма заявки работает локально:

```text
submit формы
↓
preventDefault
↓
формируется leadPayload
↓
показывается сообщение пользователю
```

Но нет боевой отправки:

```text
POST /api/leads
```

То есть сайт пока не передаёт заявку владельцу.

## Текущее состояние Telegram проекта

Второй репозиторий описывает Telegram Mini App на Flutter/Dart.

Идея правильная:

```text
Telegram
↓
Mini App URL
↓
Flutter Web App
↓
Backend API
```

Но на текущем этапе это лучше держать как отдельный подпроект внутри основного репозитория.

## Этап 1 - уведомление владельца

Первый боевой MVP:

```text
Клиент заполняет форму
↓
Сайт отправляет POST /api/leads
↓
Backend сохраняет заявку
↓
Backend отправляет Telegram-сообщение владельцу
```

Это быстрее и полезнее, чем сразу делать CRM.

## Этап 2 - Mini App

После уведомлений добавляется Telegram Mini App:

```text
Владелец открывает Mini App
↓
Видит заявки / объекты
↓
Назначает сотрудника
↓
Сотрудник видит свой объект
↓
Отправляет фотоотчёт
↓
История отображается в системе
```

## Что нужно изменить в сайте

В `script.js` в обработчике формы нужно вместо только локальной подготовки добавить отправку:

```js
await fetch('/api/leads', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
  },
  body: JSON.stringify(leadPayload),
});
```

## Что нужно сделать на backend

Минимальный endpoint:

```text
POST /api/leads
```

Он должен:

- принять данные формы;
- проверить `name` и `phone`;
- сохранить заявку;
- отправить владельцу Telegram notification;
- вернуть успех на сайт.

## Итог

Совмещать проекты нужно не через смешивание кода, а через модульную структуру:

```text
Сайт = витрина и источник заявок
Backend = обработка заявок и бизнес-логика
Telegram Bot = уведомления
Telegram Mini App = мобильная CRM
```

Такой подход не ломает лендинг и позволяет постепенно нарастить CRM-функционал.
